# Internationalization (i18n)

netlab ships an English-only catalog with a translation hook that lets consumers swap in another locale at the [`NetlabProvider`](../../src/components/NetlabProvider.tsx) level. Plan `plan/80` introduced the scaffold; real translations are additive (see `plan/81o` for the reference Japanese locale).

## TL;DR

```tsx
import { NetlabProvider } from 'netlab';

<NetlabProvider topology={topology} locale="en">
  {/* ... */}
</NetlabProvider>;
```

Inside any component:

```tsx
import { useI18n } from 'netlab';

function Title() {
  const { t } = useI18n();
  return <h1>{t('sandbox.panel.heading')}</h1>;
}
```

## Architecture

| Module                                                               | Role                                                              |
| -------------------------------------------------------------------- | ----------------------------------------------------------------- |
| [`src/i18n/types.ts`](../../src/i18n/types.ts)                       | `Catalog`, `TranslatorFn`, `TranslatorParams`, `I18nContextValue` |
| [`src/i18n/substitute.ts`](../../src/i18n/substitute.ts)             | `{{name}}` placeholder substitution                               |
| [`src/i18n/createTranslator.ts`](../../src/i18n/createTranslator.ts) | Catalog lookup with English fallback + dev warnings               |
| [`src/i18n/I18nContext.ts`](../../src/i18n/I18nContext.ts)           | React context with default English value                          |
| [`src/i18n/I18nProvider.tsx`](../../src/i18n/I18nProvider.tsx)       | Provider wired into `NetlabProvider`                              |
| [`src/i18n/useI18n.ts`](../../src/i18n/useI18n.ts)                   | Hook returning `{ locale, t }`                                    |
| [`src/i18n/locales/en.ts`](../../src/i18n/locales/en.ts)             | English catalog aggregating sub-files                             |
| [`src/i18n/locales/en/`](../../src/i18n/locales/en/)                 | Per-feature sub-catalogs (`narration.ts`, `panel.ts`, ...)        |

The `NetlabProvider` wraps its children in `I18nProvider`, so any consumer of `useI18n()` inside `<NetlabProvider locale={...}>` sees the chosen locale. Components rendered outside any provider fall back to a default English translator.

## Catalog conventions

- **Flat keys, dot-separated namespaces.** `sandbox.panel.heading`, `sandbox.narration.edit.linkState`. Keys are validated by [`catalog-completeness.property.test.ts`](../../src/i18n/__properties__/catalog-completeness.property.test.ts).
- **Top-level namespace prefix.** Currently only `sandbox.*` is allowed.
- **Placeholders use `{{name}}`.** No `{name}` or `${name}`. The substituter intentionally only knows `{{...}}`.
- **English is the source of truth.** Any locale may be a partial subset; missing keys fall back to `en` with a single dev warning per key per session.
- **One sub-catalog per UI feature.** Add a file under `src/i18n/locales/en/<feature>.ts`, then aggregate it into `src/i18n/locales/en.ts`.

## Adding a string

1. Pick a key. `<feature>.<sub-area>.<purpose>` — e.g. `sandbox.intro.step.openNodeTab.title`.
2. Add it to the appropriate sub-catalog file (or create a new sub-file and aggregate).
3. Replace the JSX literal with `{t('your.key')}`. Pass placeholder params if needed: `t('a.b', { count: 3 })`.
4. The catalog completeness property test verifies the key resolves.

```tsx
// Before
<button aria-label="Open sandbox">Sandbox</button>

// After
<button aria-label={t('sandbox.panel.openButton.label')}>
  {t('sandbox.panel.openButton.text')}
</button>
```

For non-React call sites (hook callbacks, plain functions), accept a `TranslatorFn` argument and forward `t` from `useI18n()` at the React boundary. See [`messages.ts`](../../src/sandbox/narration/messages.ts) and [`SandboxNarrationRegion.tsx`](../../src/sandbox/narration/SandboxNarrationRegion.tsx) for the pattern.

## Adding a locale

1. Create `src/i18n/locales/<lang>.ts` exporting a `Catalog` record. Keys are a subset of `en`.
2. Register it in `BUILT_IN_CATALOGS` inside [`I18nProvider.tsx`](../../src/i18n/I18nProvider.tsx).
3. Pass the locale to consumers: `<NetlabProvider locale="ja">`.

Missing keys in a non-English locale fall back to `en` automatically and log a single warning per key.

## ESLint regression gate

[`eslint-rules/no-hardcoded-sandbox-string.mjs`](../../eslint-rules/no-hardcoded-sandbox-string.mjs) flags hardcoded JSX text and translatable JSX attributes (`aria-label`, `title`, `placeholder`, `aria-roledescription`) inside files listed in `I18N_ENFORCED_FILES` in [`eslint.config.js`](../../eslint.config.js). Add a file to that list as soon as you finish extracting its strings.

The rule does not enforce globally yet — coverage is intentionally additive so legacy unswept files keep passing CI.

## What's NOT i18n'd

- Trace annotations (`plan/69`) — user-authored markdown content, not UI.
- Recording titles, snapshot names — user input.
- Demo / non-sandbox UI — out of scope for `plan/80`.
- Plural forms, gender, number/date formatting — defer to a future plan that adopts an ICU-compatible library.
- RTL layout flipping — not audited.
