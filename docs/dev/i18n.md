# Internationalization (i18n)

netlab ships an English-only catalog with a translation hook that lets consumers swap in another locale at the [`NetlabProvider`](../../src/components/NetlabProvider.tsx) level. The scaffold is in place; real translations are additive, with a reference Japanese locale provided.

## TL;DR

```tsx
import { NetlabProvider } from 'netlab';

<NetlabProvider topology={topology} locale="en">
  {/* ... */}
</NetlabProvider>;
```

Inside any component:

```tsx
import { useI18n } from 'netlab';

function Title() {
  const { t } = useI18n();
  return <h1>{t('sandbox.panel.heading')}</h1>;
}
```

English is bundled; the Japanese catalog loads on demand (REQ-356), so a consumer that never shows Japanese never downloads it (about 23 kB gzipped, in `dist/locales/ja.js`):

- `I18nProvider locale="ja"` with no `catalog` renders Japanese at once when the catalog is already loaded. On a first render before that, it renders nothing for its children until the catalog arrives, so no English frame shows. On a switch of locale, its children stay mounted in the language they had until the new one arrives.
- `preloadLocale('ja')` (from `netlab`) loads it ahead: `await` it before the first render, or before `renderToString`, and the first render is Japanese. The demo does this before it mounts.
- `import { ja } from 'netlab/locales/ja'` and `catalog={ja}` keep the fully synchronous behaviour, with the catalog in the caller's bundle.
- If the catalog cannot load, the children render in English and one warning is logged.
- The concept checks' strings, English and Japanese alike, are outside the assembled catalogs and load in chunks, only those a view needs (REQ-365):
  - `core` holds the panel's own strings and every deck's name: all the deck picker needs. Each other chunk holds one group of decks' questions: `fundamentals`, `l2`, `l2infra`, `l3`, `l4`, `l5`, `l7web`, `l7apps`, `routing`. A deck's chunk is its layer (`ConceptDeck.chunk`, set by `deck(id, layer, questions, chunk = layer)` in `src/learning/concept-check/decks.ts`); a layer-7 deck names `l7web` (DNS, DNSSEC, HTTP/1.1, HTTP/2, HTTP/3) or `l7apps` (the rest), and the layer-2 data-centre and provider lesson decks (optical, lossless, qinq, pon, tsn) name `l2infra`.
  - Files: one per deck, `src/i18n/locales/<locale>/concept/decks/<deckId>.ts`, aggregated into one file per chunk, `concept/concept-<locale>-<chunk>.ts` (export `catalog`). Built as `dist/concept-<locale>-<chunk>-*.mjs` (`concept:<locale>:<chunk>` in the size gate). `locales/<locale>/conceptCheck.ts` merges every chunk for tests and tools; production code never imports it.
  - `loadConceptChunk(locale, chunk)` in `src/components/learning/conceptCatalog.ts` loads a chunk through a fixed map of static `import()`s and keeps it. A chunk that fails logs one warning and is replaced by its English chunk (an English chunk, by nothing), so only that group shows English.
  - The panel draws nothing until the chunks its view needs are loaded: `core` for the picker, plus the deck's chunk for a deck session, plus every chunk its queue touches for a review session. On a Japanese page only the Japanese chunks load: the en/ja parity check is what guarantees no key is missing.
  - Adding a deck: add `decks/<deckId>.ts` in both locales with its questions, its name to both `concept-<locale>-core.ts`, and spread the deck file into its chunk's aggregator.
- Tests: `vitest.config.ts` preloads the Japanese catalog and every concept chunk in both locales in `src/testing/preloadLocales.ts`; a test of the loading itself starts from `vi.resetModules()`.

The `NetlabProvider` wraps its children in `I18nProvider`, so any consumer of `useI18n()` inside `<NetlabProvider locale={...}>` sees the chosen locale. Components rendered outside any provider fall back to a default English translator.

## Catalog conventions

- **Flat keys, dot-separated namespaces.** `sandbox.panel.heading`, `sandbox.narration.edit.linkState`. Keys are validated by [`catalog-completeness.property.test.ts`](../../src/i18n/__properties__/catalog-completeness.property.test.ts).
- **Top-level namespace prefix.** `sandbox.*`, `learning.*`, `simulation.*` and `editor.*` are allowed.
  `simulation.*` holds the controls every lesson shares (timeline, step controls, route
  table, hop inspector, packet structure, display filter). Hop events, drop reasons,
  protocol field names and filter syntax are codes and are deliberately not translated.
  `editor.*` holds the topology editor (toolbar, element palette and layer toggles, the
  inspector rail with its node, checks and run tabs, the Run button, and the load-failure
  messages); its canvas zoom/fit/grid controls reuse `simulation.canvas.*`.
- **Placeholders use `{{name}}`.** No `{name}` or `${name}`. The substituter intentionally only knows `{{...}}`.
- **English is the source of truth.** Any locale may be a partial subset; missing keys fall back to `en` with a single dev warning per key per session.
- **One sub-catalog per UI feature.** Add a file under `src/i18n/locales/en/<feature>.ts`, then aggregate it into `src/i18n/locales/en.ts`.

## Adding a string

1. Pick a key. `<feature>.<sub-area>.<purpose>` — e.g. `sandbox.intro.step.openNodeTab.title`.
2. Add it to the appropriate sub-catalog file (or create a new sub-file and aggregate).
3. Replace the JSX literal with `{t('your.key')}`. Pass placeholder params if needed: `t('a.b', { count: 3 })`.
4. The catalog completeness property test verifies the key resolves.

```tsx
// Before
<button aria-label="Open sandbox">Sandbox</button>

// After
<button aria-label={t('sandbox.panel.openButton.label')}>
  {t('sandbox.panel.openButton.text')}
</button>
```

For non-React call sites (hook callbacks, plain functions), accept a `TranslatorFn` argument and forward `t` from `useI18n()` at the React boundary. See [`messages.ts`](../../src/sandbox/narration/messages.ts) and [`SandboxNarrationRegion.tsx`](../../src/sandbox/narration/SandboxNarrationRegion.tsx) for the pattern.

## Adding a locale

1. Create `src/i18n/locales/<lang>.ts` exporting a `Catalog` record. Keys are a subset of `en`.
2. Register it in `BUILT_IN_CATALOGS` inside [`I18nProvider.tsx`](../../src/i18n/I18nProvider.tsx).
3. Pass the locale to consumers: `<NetlabProvider locale="ja">`.

Missing keys in a non-English locale fall back to `en` automatically and log a single warning per key.

## ESLint regression gate

[`eslint-rules/no-hardcoded-sandbox-string.mjs`](../../eslint-rules/no-hardcoded-sandbox-string.mjs) flags hardcoded JSX text and translatable JSX attributes (`aria-label`, `title`, `placeholder`, `aria-roledescription`) inside files listed in `I18N_ENFORCED_FILES` in [`eslint.config.js`](../../eslint.config.js). The list now enforces the swept sandbox, recording, snapshot, annotation, and assessment component files; add a file to that list as soon as future sandbox UI is extracted.

The rule does not enforce globally yet — coverage is intentionally additive so legacy unswept files keep passing CI.

See [Local ESLint Rules](eslint-rules.md) for the full rule catalog, fix recipes,
and the allowed escape-hatch format.

## What's NOT i18n'd

- Trace annotations — user-authored markdown content, not UI.
- Recording titles, snapshot names — user input.
- Demo / non-sandbox UI — out of scope for the i18n scaffold.
- Plural forms, gender, number/date formatting — defer to a future plan that adopts an ICU-compatible library.
- RTL layout flipping — not audited.
