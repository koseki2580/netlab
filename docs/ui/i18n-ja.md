# 日本語 i18n ガイド

Netlab の UI 文言は `src/i18n/locales/en.ts` を基準に管理します。日本語ロケールは `src/i18n/locales/ja.ts` から公開され、同じキー集合と同じプレースホルダー名を持つ必要があります。

## 新しいロケールを追加する手順

1. `src/i18n/locales/en/` と同じ分割で、新しいロケール用のディレクトリを作る。
2. 各ファイルで `Catalog` を満たすオブジェクトを export する。
3. ロケール集約ファイルを `src/i18n/locales/<locale>.ts` に作り、`en.ts` と同じ順序で結合する。
4. `I18nProvider` の組み込みカタログに登録し、必要なら `src/i18n/index.ts` から export する。
5. `npm run i18n:check` を実行し、キー差分とプレースホルダー差分がないことを確認する。

## `i18n:check` が見るもの

`npm run i18n:check` は `en` と `ja` のカタログを読み込み、次の差分を失敗として扱います。

- `en` にあるのに `ja` にないキー
- `ja` にだけ存在する余分なキー
- `{{count}}` や `{{nodeId}}` などのプレースホルダー名の不一致

文の自然さまでは機械判定しません。日本語は直訳よりも、ネットワーク学習者が迷わず読める表現を優先します。

## 翻訳してはいけないもの

- `{{count}}`、`{{label}}` のようなプレースホルダー名
- `TCP`、`DHCP`、`NAT` などのプロトコル略語
- コードスパン内の識別子、ファイルパス、CLI コマンド
- Markdown リンクの URL やアンカー
- テストや URL 復元に使うキー名

## レビュー時の確認

翻訳を変えたら、`npm run i18n:check` と対象 UI のテストを実行します。Gallery の言語トグルは `localStorage` の `netlab-locale` に選択を保存するため、ブラウザで日本語表示が reload 後も残ることを確認します。
